## Proposed minimal restrictive contract for owner review (not implemented)

- New self-registered/Google identities start as `user` with no tenant; preserve existing provisioned roles. Only an existing DB-backed superadmin assigns elevated roles and tenant ownership; no implicit first-user bootstrap.
- Resolve actor from current DB user for every admin operation; missing actor, missing scope or unrecognized role denies. Global token validation alone never proves current role/tenant membership.
- Superadmin has explicit company/brand/team/user/vendor/provider administration, safe secret presence indicators and write-only secret replacement; only superadmin mutates global provider catalog, creates/deletes companies or assigns admin/coordinator/superadmin. Do not expose credentials in ordinary detail responses.
- Admin/coordinator may list/detail/edit existing authorized company, brands, teams, users and vendors only within actor.companyId (or exact actor.teamId where no company); role/tenant reassignment, peer/elevated management and destructive company deletion deny. Other roles receive only product-required own-team runtime safe reads through scoped endpoints, never management mutations.
- Resolve record tenancy server-side through Company.id, Brand.companyId, Team.brand.companyId, User.companyId/team.brand.companyId, Vendor.team.brand.companyId, tenant config/profile companyId. Conflicting company/team bindings deny. Cross-tenant IDs return a uniform denied/not-found result before service mutation. Caller tenant filters must intersect actor scope.
- Use per-endpoint guard/policy metadata or request-aware service methods, not a blanket CrudController guard: that controller also serves runtime launch, session, knowledge and webhook operations. Preserve webhook's distinct secret guard; restrict migrate/seed maintenance explicitly to superadmin without executing them.
